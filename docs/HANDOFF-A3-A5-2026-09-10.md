`agent-20260910T230218-0f2a3ffd`, seed 20260910, `--clock realtime

```

```

**The cache result is the headline infrastructure number.** 99.23% against a
97% target, measured over 235 real decisions, and it is what makes a 30-minute
run cost 74 cents instead of tens of dollars. Prefix caching is automatic and
DeepSeek reports the split (`prompt_cache_hit_tokens` /
`prompt_cache_miss_tokens`), which is what the accounting depends on — an
unreported split is priced as all-miss, and hit against miss is 50x.

**119 iron plates came out of machines the agent built and fuelled**, with the
by-hand columns proving they were not crafted. It found coal 80 tiles away,
carried it back, and ran a smelting line. That is a real result on a hard seed.

It did **not** automate beyond that, and that part is genuinely the agent's:
its drill's output tile was inside its furnace's footprint (correctly
connected), the furnace stalled on `waiting for space in destination` with its
output full, and a `burner-inserter` and an `iron-chest` sat unplaced in its
inventory the whole time.

## 3. What got caught

Nine defects. **Eight were the environment showing the agent less than the game
offers.** The recurring shape is worth naming because it will recur:

> **A domain must not advertise values the runtime always refuses.**

Four instances of exactly that, each costing a live run real decisions:

| domain | offered | handler always said |
|---|---|---|
| `placements` | the character's own tile | `collision` |
| `technologies` | 7 trigger-completed techs | `tech_not_selectable` |
| `targets` | resource handles with no positions | `out_of_reach` on the far ones |
| `recipes` | every *unlocked* recipe | `no_items` for unaffordable ones |

In every case the **handler already knew the rule** and the domain did not.
`H.research` even carried a comment explaining trigger technologies while the
published frontier ignored it. A cheap standing check for the next person:
for each argument domain, ask what the handler rejects unconditionally, and
whether the domain can still produce it.

### The rest

1. **Watching the run changed the world.** 0 crash-site entities headless, **34
   wrecks holding 16 items** once a client attached — the base scenario builds
   the introductory wreckage when a player appears. A1.2 forbids the viewer
   altering the agent's inventory; A1.1 forbids the wreck bonuses. Both were
   broken *by the act of watching*, and the agent looted those items.
   **This invalidates runs 1–3.** Fixed by sweeping `crash-site-*` on join;
   re-measured 0 before and 0 after.

2. **`can_place_entity` on the character's own tile is `false`.** Every run
   opened by walking to a tile then building on it. `_placement_candidates`
   computed `here` and never read it — the ninth "declared, never read" in this
   repo. The unit test *pinned the defect*, asserting the tile was a candidate.

3. **Orientation was a word, not a location.** "facing south" does not say which
   tile a drill's ore lands on. Machines now publish `outputs onto (x, y)` and
   `takes from (x, y)`. The inserter is why it matters: it takes from *behind*
   itself, so `facing north` and outputting south are both true.

4. **A stopped machine looked identical to a running one.** Uppercase glyph runs,
   lowercase is stopped, and the line says `NO FUEL`. Two runs built three
   machines, fuelled none, and read the map as a finished factory.

5. **Anything past 8 tiles stopped existing.** The agent built a second smelter,
   walked off, and never came back — no observation could have reminded it.
   `YOUR FACTORY` now lists every machine of the player force at any distance
   with fuel, status and both connection tiles.

6. **`mine` never said it removes things**, and `rotate` never said it moves the
   output tile. Both capabilities existed and worked since A2; nothing told the
   agent what they were for. `rotate_at` was used twice in five runs.

7. **RCON lost replies silently under concurrency.** Two threads allocate ids
   from a plain counter and a lower-id reply is drained as stale, so one
   thread's answer dies inside the other's read loop. Removing the lock turns
   the new test into two `unexpected rcon packet id` errors and two timeouts.

8. **`RunClock` published a false claim** — `"final snapshot excluded"` while
   `clock.stop()` ran after the save. And the world was *still running* during
   `game.server_save`: 59 ticks of drift, now 1, which is the engine floor.

### Two I got wrong and the engine corrected

- I claimed a loose item pile **blocks placement**. It does not —
  `can_place_entity` returns true on a tile holding 7 iron ore, for every
  build-check type.
- I claimed **`mine` clears a pile**. It does not — `item-on-ground` has
  `minable = true` and **no products**. Pickup is a separate operation the
  catalog does not expose.

Both had already been written into the prompt as instructions before I checked.
Check mechanics against the engine before telling the agent about them.

## 4. Exploration — fixed after this handoff was first written

**The world charted 192x192 tiles and published none of it.** That was the
biggest open item and it is now closed.

`OPEN_FACTORY` charts a square at creation, so the force knew where everything
was; the agent's `RESOURCES` block only listed what was inside its 32-tile
sensor. On seed 20260910 the word "stone" never appeared in a prompt, which is
why "go and find stone" never happened -- it was never told stone exists.

`open_world` now surveys every resource patch in the charted area and the agent
reads it once, in the cached prefix:

```
=== THE CHARTED MAP ===
  iron-ore:   468 tiles centred on (-47, -8),   48 tiles northwest
  copper-ore: 401 tiles centred on (-52, -53),  74 tiles northwest
  coal:       282 tiles centred on (-89, -10),  89 tiles northwest
  stone:      182 tiles centred on (-9, -112), 112 tiles northwest
```

1,283 characters, paid once. `chart_radius` went 96 -> 192, because stone at 112
tiles was outside the old square entirely.

Two traps on the way, both worth knowing:

- **Charting reveals chunks; it does not generate them.** The first survey
  scanned ground that did not exist and returned zero patches.
- **`handle_open_world` names every field it passes through**, so the survey was
  computed, returned, and dropped by the handler. Tenth "declared, never read".

Measured distances from spawn on this seed, for reference:

```
iron-ore     28.5 tiles      coal      79.7
copper-ore   62.9            trees     81.0        stone   104.8
```

The agent still starts with **one wood**, about 22 seconds of furnace burn.
**Unproven in a live run** -- the survey landed after run 5 finished.

## 5. Also open

- **A5.3 report not written.** `tools/run_report.py <run-id> --out ...` produces
  everything except the ranked fixes, which are deliberately left for a person.
- **Two engine tests fail and are not ours.**
  `test_observation_profiles_decode_identically[navigate]` and `[deliver]`
  assert `local-v2` sends fewer bytes than `local-v1`; it now sends slightly
  more (95,015 against 94,985). Confirmed pre-existing on the previous commit.
  Nothing in the A-series uses `local-v2`, but this is a real regression in a
  benchmark contract.
- **`mine` is ongoing and agents keep batching it.** Every run issued several
  `mine_at` in one reply and got `busy` on the second, including
  `wait+mine_at+wait+mine_at`. The description now says one per reply; unproven
  in a live run.
- **No pickup verb.** Loose piles can be built over but not collected.
- **Vision deferred.** `capture.py` works when a client is attached — measured,
  two real 512×512 frames — and the frame lands in the *client's*
  `script-output`, not the worker's, which is why `capture.py` currently raises.

## 6. Worth knowing before changing direction

FLE (Factorio Learning Environment) solves the spatial half differently: it
gives agents `connect_entities`, which runs belts/pipes/power between two
entities with pathfinding built in, plus a Python REPL where the agent's own
program output *is* the observation. Their reported failure modes are exactly
what we watched — "agents frequently place entities incorrectly, causing
gridlock" and "fell into a loop of greedily repeating the same fix".

So this is the known hard part, not a defect unique to this environment. But a
`connect` verb would be a **significant assistance grant** and this repository
requires assistance to be declared (`assistance=("navigation",
"bounded-sequences:8")` today). Adding pathfinding-based connection makes results
incomparable to runs without it. That is a decision for the owner, not a
refactor.

## 7. How to run it

```bash
uv run factoriorl preflight                    # full go/no-go, ~5 min
uv run factoriorl preflight --live             # + one capped provider call

uv run factoriorl agent --task open_factory --clock realtime --launch-client \
    --model deepseek-flash --base-url https://api.deepseek.com/v1 \
    --api-key-env DEEPSEEK_API_KEY --thinking --reasoning-effort low \
    --max-tokens 8192 --max-cost-usd 2 --max-wall-seconds 1800

uv run python tools/run_report.py <run-id> --out docs/evidence/a5-first-run.md
uv run factoriorl replay <run-id>
```

Seed 20260910 stays. A1.1 says "do not reroll after seeing an inconvenient map",
and that clause exists precisely so a result is earned rather than chosen.
